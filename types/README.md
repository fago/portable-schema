# Types

The generic type library: reusable schemas with stable `$id`s that any integration can reference.

Only system-independent types go here. Framework types, such as Drupal's config schema types, plugin settings or catalogs of bundles and plugins, are generated by the integration from the system it describes. See [`fixtures/examples/drupal`](../fixtures/examples/drupal) for how that looks.

## Primitives

Every primitive has a named type ([decision 0004](../docs/decisions/0004-types-for-all-primitives.md)). Types use registry formats inside.

## Candidates

Shapes, not decided yet: `link` (`uri` + `title`), `image` (`src`, `alt`, `width`, `height`).

## Rules

- **Use sites add their own constraints** next to the `$ref`, e.g. `{"$ref": "portable:label", "maxLength": 255}`.
- **Plain types and formats stay valid.** `{"type": "string", "format": "uri"}` behaves like `portable:uri`, since widget resolution and adapters key on the format and type keywords.
- **Types can carry their own messages** (`x-portable-messages`), so every use gets the same wording.
- **Each type is a stable reference.** Consumers match types by `$ref`, never by comparing resolved schema structure.
- **Base types of objects stay open** (no `unevaluatedProperties: false`). Concrete types close the object.
- **Time values use the standard formats.** Systems that store times without an offset add it when converting.
